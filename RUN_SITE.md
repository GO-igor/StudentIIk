# Как запустить сайт Ишки у себя (Mac)

Сайт — это две страницы: **вход** и **главная с чатом**. Открываются в браузере по адресу http://localhost:8000.
Работают они через `backend/server.py`: он отдаёт страницы из папки `frontend/` и передаёт сообщения той же Ишке,
что и терминальный чат (`chat.py`). Аккаунты по-прежнему заводятся в терминале (`accounts.py`), а терминальный чат остаётся:
сайтом и терминалом можно пользоваться одновременно, даже под одним аккаунтом.

Нужны три окна Терминала (Cmd+N открывает новое): в окне 1 работает модель, в окне 2 сайт, а окно 3 — для команд
(аккаунты, чат в терминале). Для уведомлений в Telegram — ещё одно.

**Один раз**, если проекта `~/StudentIIk` ещё нет, выполни блок «Один раз» в начале
[backend/RUN_QUICK.md](backend/RUN_QUICK.md): он скачает проект, подготовит Python и перенесёт базу с аккаунтами.
Если проект уже есть, но в нём нет `.venv`, скачивать его заново не нужно. Последняя строка перенесёт базу
с аккаунтами из старой папки, только если здесь её ещё нет (своя база не тронется):

```bash
cd ~/StudentIIk/backend
python3 -m venv .venv
source .venv/bin/activate
pip install jinja2
cp -n ~/ishka-assistant/db/ishka.sqlite db/
```

Ничего нового ставить не нужно: сайту хватает того же `jinja2`, что и чату.

## Окно 1. Сервер с моделью

Как и для чата в терминале:

```bash
cd ~/ishka-model
llama-server -m ishka-Q4_K_M.gguf --jinja -c 16384 --port 8080
```

Готово, когда появилась строка `server is listening on http://127.0.0.1:8080`. Окно не закрывай.

## Окно 2. Сайт

```bash
cd ~/StudentIIk/backend
git pull
source .venv/bin/activate
python server.py
```

Появится строка `Сайт Ишки: http://localhost:8000`. Открой этот адрес в браузере (Safari, Chrome — любой).
Окно не закрывай: пока оно открыто, сайт работает. Остановить: Ctrl+C.

1. Откроется страница **входа**. Введи логин и пароль аккаунта из `accounts.py` или нажми «Продолжить без входа».
2. После входа откроется **главная**: чат с Ишкой. Пиши вопрос и жми Enter (Shift+Enter — новая строка) или нажми
   на одну из подсказок. Под ответом видно, откуда Ишка взял данные: «расписание», «заметки» и т. д.
3. Сработавшие напоминания и утренний брифинг (с 7:30 до 12:00, первый раз за день) появляются в чате сами,
   пока страница открыта: она проверяет их раз в 30 секунд. Если студент подключил Telegram и запущено окно
   уведомлений, напоминания приходят в Telegram, а в чате — только те, что бот не успел отправить.
4. «Новый чат» (слева вверху) — начать разговор с чистого листа (заметки и напоминания остаются), «Выйти» — выйти из аккаунта.

Страницу можно перезагрузить, даже пока Ишка отвечает: история останется, а ответ появится, когда будет готов.
Две вкладки одного браузера — один разговор, другой браузер или телефон — свой. Войти снова нужно после перезапуска
`server.py` или если сайт не открывали 12 часов (без аккаунта — 6): тогда и разговор начнётся заново.

## Окно 3. Аккаунты и чат в терминале

Окна 1 и 2 заняты моделью и сайтом, поэтому команды — в отдельном окне (Cmd+N), где сначала выполнено
`cd ~/StudentIIk/backend && source .venv/bin/activate`. Сайт останавливать не нужно.

| Что сделать | Команда |
|---|---|
| завести студента | `python accounts.py add ivanov --group 8К51 --subgroup 2 --english Аксёнова --name "Иван Иванов"` |
| завести старосту | `python accounts.py add petrova --group 8К51 --role starosta --name "Анна Петрова"` |
| посмотреть все | `python accounts.py list` |
| поменять профиль | `python accounts.py edit ivanov --subgroup 1` — на сайте подхватится сразу, перезаходить не нужно |
| сменить пароль | `python accounts.py passwd ivanov` — все входы этого аккаунта на сайте сбросятся |
| удалить | `python accounts.py remove ivanov` |

Чат в терминале работает как раньше, в этом же окне: `python chat.py --login ivanov`. Его можно держать открытым
вместе с сайтом, даже под тем же аккаунтом: у каждого свой разговор, а заметки и напоминания общие.

## Окно 4 (по желанию). Уведомления в Telegram

Как раньше, см. «Уведомления в Telegram» в [backend/RUN_QUICK.md](backend/RUN_QUICK.md). Там это окно называется
«окно 3», а проверку `python notify.py --once …`, которую там выполняют «в окне 2», выполняй в окне 3 (для команд):

```bash
cd ~/StudentIIk/backend
source .venv/bin/activate
python notify.py
```

## Полезные флаги `server.py`

| Флаг | Что делает |
|---|---|
| `--port 8001` | другой порт сайта, если 8000 занят (адрес тогда http://localhost:8001) |
| `--url http://localhost:8081` | модель на другом порту (как у `chat.py`) |
| `--now "2026-10-15 08:00"` | подменить время для проверки: увидишь брифинг и напоминания этого утра. Часы стоят, прошедшее из базы не удаляется, но записанное в чате (заметки, объявления старосты) сохраняется. Чтобы не задеть настоящих студентов, проверяй на копии базы: `cp db/ishka.sqlite /tmp/test.sqlite` и `--db /tmp/test.sqlite` |
| `--debug` | печатать в окне запросы, вызовы инструментов и ответы модели |
| `--api openai --url http://localhost:11434/v1 --name ishka` | модель через Ollama (`pip install openai`) |
| `--host 0.0.0.0` | открыть сайт телефону в той же Wi-Fi сети: http://АДРЕС-МАКА:8000 (адрес — в «Системные настройки → Wi-Fi → Подробнее»). Соединение без HTTPS, поэтому только дома, не в общей сети |
| `--db путь` | другая база аккаунтов (как у `accounts.py --db`) |

Без модели (окно 1 закрыто) сайт тоже откроется и вход будет работать, а на вопросы Ишка ответит
«Не получилось ответить» и подпишет причину: сервер модели не отвечает.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `Address already in use` при запуске `server.py` | сайт уже запущен в другом окне, или порт занят: `python server.py --port 8001` |
| `command not found: python` | не активировано окружение: `cd ~/StudentIIk/backend && source .venv/bin/activate` |
| `Нет страниц сайта` | `server.py` запущен не из проекта StudentIIk или папка `frontend` не скачалась: `git pull` |
| страница без оформления, вход не работает | открыт файл `index.html` напрямую; открывай адрес http://localhost:8000 |
| «Сайт не отвечает: запущен ли server.py?» | окно 2 закрыто или `server.py` остановлен: запусти снова и войди |
| в ответе «сервер … не отвечает: запущен ли llama-server в окне 1?» | запусти окно 1 и дождись `server is listening` |
| «Вход по аккаунтам пока не настроен» | базы аккаунтов нет (об этом пишет и окно 2): заведи аккаунт (таблица выше) или скопируй базу из старой папки: `cp ~/ishka-assistant/db/ishka.sqlite ~/StudentIIk/backend/db/` |
| «Неверный логин или пароль» | `python accounts.py list` — правильный ли логин; новый пароль — `python accounts.py passwd ЛОГИН` |
| «Слишком много неудачных попыток» | пять неверных входов за 5 минут с этого компьютера (под любым логином): подожди 5 минут, до этого не пустит и с верным паролем |
| «Открой сайт по адресу http://localhost:ПОРТ» | сайт открыт по чужому имени; открывай http://localhost:8000 (с телефона — по IP-адресу Мака) |
| «Ошибка на сервере» | подробности — в окне 2; пришли их разработчику |
| после входа сразу снова страница входа | сменили пароль или удалили аккаунт — войди заново; если так при каждом входе, проверь, что куки для localhost в браузере не запрещены |
| Ишка отвечает странно | проверка модели — в `~/ishka-assistant` (шаг 7 RUN_MAC.md: `python diag_server.py ...`) |
| Ишка неверно отвечает про ТПУ (общежитие, стипендия, контакты) | поправь поле в `backend/db/university.json` — сайт увидит правку со следующего вопроса, перезапускать не нужно. Чтобы правка попала и в `ishka-assistant`, скопируй файл туда же (`db/university.json`) |

## Где что лежит

| Путь | Что это |
|---|---|
| `frontend/login.html`, `frontend/index.html` | страница входа и главная с чатом |
| `frontend/css/style.css` | оформление: цвета, тени и скругления — переменные в начале файла |
| `frontend/js/login.js`, `frontend/js/chat.js`, `frontend/js/api.js` | вход, чат и запросы к серверу |
| `frontend/img/`, `frontend/fonts/` | Ишка, значок вкладки и шрифт Manrope (лежит в проекте, интернет не нужен) |
| `backend/server.py` | сайт: страницы и API (`/api/login`, `/api/chat`, `/api/updates` …), описание — в начале файла |
| `backend/ishka.py` | сам диалог: модель, инструменты, запретные фразы, напоминания и брифинг; общий для сайта и `chat.py` |
